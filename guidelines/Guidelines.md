Keep NewBee Merchant Portal screens professional, trustworthy, modern, and visually consistent while allowing product features, pages, modules, and business flows to evolve freely.
---

You are designing screens for the NewBee Merchant Portal.

NewBee Merchant Portal is the merchant-side B-end workbench for a Hong Kong staffing and recruitment platform. Merchants use it to manage business-related hiring, verification, credit, job posting, scheduling, settlement, and other operational tasks as the product evolves.

This skill controls design consistency, not product scope.

Future pages, modules, components, and business flows may change freely. Do not restrict new functionality based on existing pages. When designing a new page, satisfy the actual product requirement first, then apply the NewBee merchant-side design language.

Product feeling

The merchant portal should feel:

Professional
Trustworthy
Modern
Clean
Business-oriented
Efficient
Friendly but not casual
Lightweight but still B-end

It should feel like a reliable merchant workbench, not a consumer app, a heavy ERP system, or a generic admin template.

Every new screen should feel like it belongs to the same NewBee Merchant Portal.

Visual direction

Keep the existing approved merchant-side visual direction:

Clean modern SaaS style
Light background
White card-based content structure
Clear dashboard hierarchy
Strong primary actions
Calm blue brand accent
Spacious and readable layout
Professional but not heavy

The design should be polished and credible, while staying simple enough for merchants to use comfortably.

Consistency rules

When creating new screens, keep the overall style consistent with the approved merchant-side pages in:

Color usage
Typography hierarchy
Card and panel style
Button style
Form and input style
Sidebar and top bar feeling
Icon style
Spacing rhythm
Status tag style
Empty, loading, success, warning, and error states

Do not introduce a completely new visual direction unless explicitly requested.

Component principle

Reuse existing component patterns when they fit the new requirement.

If a new feature requires a new layout or component, create it as needed. New components are allowed, but they should feel visually compatible with the existing NewBee merchant design system.

Do not force new functionality into old components if it harms usability.

Layout principle

Merchant-side pages should be clear, practical, and action-oriented.

For dashboard and management pages, prioritize:

Clear page title and context
Main business action
Key business status
Simple data cards or summaries
Forms, tables, calendars, or lists when the task requires them
Clear primary and secondary actions

The merchant portal can grow over time. New modules may require different layouts, but the page should still feel like the same product.

Copywriting and terminology

The product may support multiple UI languages, including Simplified Chinese, Traditional Chinese for Hong Kong users, and English.

Do not lock the interface language to only one language.

However, business terminology should stay consistent with the NewBee product system and should align with Hong Kong staffing and employment usage.

When Chinese is used, prefer wording that is natural for Hong Kong labor and staffing scenarios, and keep it consistent with the C-end product.

Use concise, business-oriented wording.

Preferred terminology examples:

Job / position: 職位 / 职位
Create job: 建立職位 / 创建职位
Apply: 申請 / 申请
Schedule / shift arrangement: 排班
Check-in / attendance punch: 打卡
Attendance correction: 補卡 / 补卡
Wage payout / salary payment: 出糧 / 出粮
Wallet / accounting balance: 錢包 / 钱包
Merchant: 商戶 / 商户
Worker / employee: 雇員 / 雇员
Verification: 認證 / 认证
Credit limit: 授信額度 / 授信额度
Used credit: 已佔用額度 / 已占用额度
Remaining credit: 剩餘額度 / 剩余额度
Review / approval: 審核 / 审核
Approve: 通過 / 通过
Reject: 駁回 / 驳回
Settings: 設定 / 设置
Details: 詳情 / 详情
Notification: 通知

Use “出糧 / 出粮” for wage payout or salary payment in the NewBee staffing context instead of generic wording like “发工资”.

Avoid overly emotional, promotional, or consumer-style wording.

Product evolution rule

This skill must not freeze the product.

NewBee Merchant Portal may add, remove, or change modules over time.

Do not reject or weaken a new feature because it was not included in previous pages.

Design the right structure for the new requirement, then apply the established NewBee merchant-side visual language.

Anti-drift check

Before presenting a new screen, silently check:

Does this still feel like NewBee Merchant Portal?
Is it professional, trustworthy, and merchant-facing?
Is the visual style consistent with the approved merchant-side pages?
Are colors, typography, cards, buttons, forms, navigation, icons, and spacing generally aligned?
Is the copy clear and consistent with NewBee terminology?
Does the design support the new feature without over-restricting product evolution?

If not, revise the design before presenting it.
